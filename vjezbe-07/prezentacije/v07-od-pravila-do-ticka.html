G · Povrat i prvo izdvajanje novca

A4 §5„Svake 4. sedmice domaćinstvo iz kućnog budžeta izdvaja 4 KM za alat i popravke [P]. Novac se akumulira do trošenja.“

Predviđanje u chatu
Za ticks = 3, da li već sada ide uplata?

C# · analogija
foreach (var d in PozajmiliAlat()) {
    d.Posudba = 0; centar.Raspolozivo++;
}
if ((ticks + 1) % 4 == 0)
    foreach (var d in domacinstva) d.Budzet += 4;

ask centar mijenja polje patcha, a vanjski ask polje domaćinstva.

NetLogo · isječak iz v07-tick.nlogox
to povrat-i-uplata
  ask domacinstva with [posudba = 1] [
    set posudba 0
    ask centar [set raspolozivo raspolozivo + 1]
  ]
  if (ticks + 1) mod 4 = 0 [
    ask domacinstva [set budzet budzet + 4]
  ]
end

Zašto ovako

Sedmica koju obrađujemo je ticks + 1. Prvo izdvajanje je u sedmici 4. Povrat čuva posljednje iskustvo.

Zašto ne drugačije

Provjera · Command Center, posmatrač

Prije sedmice 4, ticks je 3 i izraz daje true. Poslije izvršenog go ticks je 4.

H · Potreba, odluka, pa budžet

A4 §5„Ako je budžet manji od naknade, zahtjev se ne šalje i bilježi se kao „ograničen budžetom“.“

Predviđanje u chatu
Bez odluke o traženju, da li brojimo ograničenje budžetom?

C# · analogija
if (!TrebaAlat(d)) continue;
d.Potreba = true; potrebeSedmica++;
if (!ZeliPosudbu(d)) continue;
if (d.Budzet >= naknada) d.Zahtjev = true;
else ogranicenjaSedmica++;

Tijelo foreach petlje. Obje funkcije porede rng.NextDouble() s p-potrebe, odnosno stav.

NetLogo · isječak iz v07-tick.nlogox
to formiraj-zahtjeve
  ask domacinstva [
    if random-float 1 < p-potrebe [
      set potreba? true
      set potrebe-sedmica potrebe-sedmica + 1
      if random-float 1 < stav [
        ifelse budzet >= naknada [
          set zahtjev? true
        ] [
          set ogranicenja-sedmica ogranicenja-sedmica + 1
        ]
      ]
    ]
  ]
end

Zašto ovako

Ograničenje budžetom opisuje spriječeni zahtjev. Bez potrebe ili odluke nema tog ograničenja.

Zašto ne drugačije

Brojanje svih s malim budžetom uključilo bi i domaćinstva koja nisu htjela posuditi alat.

Provjera · Command Center, posmatrač

show (list potrebe-sedmica count domacinstva with [zahtjev?])

Broj zahtjeva može biti manji od broja potreba. Jednake vrijednosti nisu obavezne.

I · Slučajni red dodjele

A4 §5„Centar obrađuje zahtjeve slučajnim redom. Dok ima alata, dodjeljuje komad, raspolozivo − 1, budžet − naknada, iskustvo = 1.“

Predviđanje u chatu
Da li domaćinstvo plaća naknadu ako je centar ostao bez alata?

C# · analogija
if (centar.Raspolozivo > 0) {
 centar.Raspolozivo--; d.Posudba = 1;
 d.Budzet -= naknada; d.Iskustvo = 1;
 d.PosudioIkada = true; posudbeSedmica++;
} else {
 d.Iskustvo = 0; odbijanjaSedmica++;
}

C# tijelo foreach petlje nad promiješanim zahtjevima. NetLogo ask bira slučajan red.

NetLogo · isječak iz v07-tick.nlogox
to dodijeli-alat
  ask domacinstva with [zahtjev?] [
    ifelse [raspolozivo] of centar > 0 [
      ask centar [set raspolozivo raspolozivo - 1]
      set posudba 1
      set budzet budzet - naknada
      set iskustvo 1
      set posudio-ikada? true
      set posudbe-sedmica posudbe-sedmica + 1
    ] [
      set iskustvo 0
      set odbijanja-sedmica odbijanja-sedmica + 1
    ]
  ]
end

Zašto ovako

Alat i naknada mijenjaju stanje samo pri uspjehu. Ograničenje budžetom ostavlja prethodno iskustvo.

Zašto ne drugačije

Stalan red po who davao bi ranijim domaćinstvima stalnu prednost. Naplata prije provjere zalihe naplatila bi i odbijeni zahtjev.

A4 §6„Omjer uspješnih posudbi i nastalih potreba.“

Predviđanje u chatu
Ako nije nastala nijedna potreba, da li je zadovoljeno 0 % potreba?

C# · analogija
double? ZadovoljenePotrebe() =>
 potrebeUkupno == 0 ? null
 : (double)posudbeUkupno / potrebeUkupno;

Nullable rezultat označava odsustvo omjera. NetLogo reporter vraća tekst „nedefinisano“.

NetLogo · isječak iz v07-tick.nlogox

  report count domacinstva with [posudio-ikada?] / count domacinstva
end

Završeni model za poređenje · Kod za copy-paste · Povratak na V07

Na V08 dodajemo razgovor, pratimo promjenu stava i čitamo grafove kroz 52 sedmice. Na V09 slijede poređenja u BehaviorSpaceu.

Ako ostane vremena · izbor 5–10 min

Rezerva · tri dodatne provjere

  1. Zamijenite B pa A redom A pa B u ručnoj sedmici. Koje ukupne mjere ostaju iste, a čiji se ishod mijenja?
  2. Postavite naknada = 0. Može li još postojati ograničenje budžetom? Može li se javiti nestašica?
  3. Privremeno pomjerite uplatu na ticks mod 4 = 0. Provjera G treba otkriti uplatu u prvoj sedmici. Zatim vratite ispravni kod.

Dodatni izazov

Sačuvajte niz sedmičnih brojača za 52 sedmice, pa ponovite s istim seedom i istim parametrima. Poredite cijeli niz. Različita C# implementacija ne mora dati isti niz kao NetLogo.
